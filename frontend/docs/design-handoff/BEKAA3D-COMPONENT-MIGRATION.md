# Bekaa3D: Component Migration Map

Status: **planning only**. No component has been changed.

Each current reusable component is mapped to its Stitch pattern (§ numbers refer to [COMPONENT-SPECS.md](./COMPONENT-SPECS.md)) and given a class:

| Class | Meaning |
|---|---|
| **A** | Style-only change: swap classes/tokens; markup, props, and behaviour unchanged |
| **B** | Structural visual change (new wrappers, layout, slots, variants) while behaviour, props contract, ARIA, and data flow stay intact |
| **C** | New reusable visual component is justified (no current equivalent; needed by ≥2 routes or by a shell) |
| **D** | Keep the current structure because Stitch lacks behaviour the real app needs; apply Stitch styling only |
| **E** | No change required |

Inventory method: every file under `src/components/**` (excluding tests) was listed, and the shells, primitives, and highest-traffic components were read. Counts: `src/components` holds **116 component files** (`.tsx`, non-test) plus 6 `.ts` registries/types. **All 116 are named below, in 98 mapping rows** (some rows group closely related files, e.g. the address components). The 2 nav registries (`accountNavItems.ts`, `adminNavItems.ts`) are mapped with their shells; the 4 type-only files need no change. Further rows cover new components or decisions (Container, PageHeader, AppTopBar, drawer, Skeleton, KpiCard, Breadcrumbs, header account entry, trust tiles).

**Rules for every row**
- Keep every `aria-*`, `role`, `id`/`htmlFor` linkage, `useId`, `ref` prop, `isBusy`/`isLoading` guard, focus-return, and `aria-current` exactly as is.
- Keep visible text that tests or E2E locate by (`getByRole(name)`, `getByLabel`, `getByText`). Stitch labels are UPPERCASE through CSS (`uppercase`), never by rewriting the source string, because accessible names must stay unchanged. Note: `text-transform` does not change the accessible name in Chromium.
- Do not introduce Stitch-only features (reviews, ratings, discounts, STL downloads, analytics, social login, card-number fields) that have no backend.
