# Bekaa3D: Route Migration Map

Status: **planning only**. No route, page, or layout was changed.

Every route mounted under `src/app` is listed: **51 `page.tsx` routes** (49 render UI, 2 are server redirects) plus **3 app-level surfaces** (`not-found.tsx`, `error.tsx`, `global-error.tsx`). Stitch page codes (S1–S9, A1–A4, C1–C7, D1–D15) refer to the [PAGE-SPECS.md inventory](./PAGE-SPECS.md#page-inventory). Original files live in `docs/design-reference/stitch/<folder>.html`.

> **The repo contains the Stitch HTML only. No `screen.png` files were copied** (`docs/design-reference/stitch/` holds 35 `.html` files). The 1280px screenshot comparison in the QA workflow needs those PNGs added (for example as `docs/design-reference/stitch/screens/<folder>.png`), or it needs the HTML rendered locally. Rendering requires network access, because the files load the Tailwind CDN and remote fonts and images.

**Confidence**
- **HIGH:** a Stitch page designs this route's purpose and most of its sections.
- **MEDIUM:** a Stitch page matches the purpose, but the real route's content, data, or flow differs materially (some Stitch sections dropped, real sections not designed).
- **DERIVED:** no Stitch page exists. The route is styled from the Stitch system (shell, components, tokens) only. **No Stitch screen is invented.**

**Shells** (see [BEKAA3D-COMPONENT-MIGRATION.md](./BEKAA3D-COMPONENT-MIGRATION.md) §1): `Storefront` = Header + Footer + WhatsApp FAB + `Container` · `Auth` = Storefront chrome + a centred auth card on the blueprint canvas (the app keeps the header and footer on auth pages, unlike Stitch, so users can navigate away) · `Account` = `AccountLayout` inside the storefront chrome · `Admin` = `AdminShell` (sidebar + top bar; storefront chrome suppressed, Batch 9).

**Risk scale:** L = restyle only · M = layout or structure changes around stateful UI · H = touches a money, auth, or fulfilment flow or a high-coupling E2E assertion.
